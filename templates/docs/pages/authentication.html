Authentication

Google OAuth setup, dev mode, user roles, and the invite system.

Authentication Modes

The app supports two authentication modes:

ModeWhenUse Case
Dev LoginGOOGLE_CLIENT_ID is not setLocal development — log in with any email
Google OAuthGOOGLE_CLIENT_ID is setProduction — requires Google account

Dev Login Mode

When no Google OAuth credentials are configured, the app shows a simple email form. Enter any email to log in instantly with admin + trader roles. This is designed for local development only.

Warning

Dev login mode bypasses all authentication. Never deploy to production without setting GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET.

Google OAuth Setup

1. Create a Google Cloud Project

  1. Go to the Google Cloud Console
  2. Create a new project or select an existing one
  3. Navigate to APIs & Services → OAuth consent screen
  4. Configure the consent screen (External user type for most cases)
  5. Add scopes: email, profile, openid

2. Create OAuth Credentials

  1. Go to APIs & Services → Credentials
  2. Click Create Credentials → OAuth client ID
  3. Application type: Web application
  4. Add authorized redirect URI: https://your-domain.com/auth/callback
  5. For local dev: http://localhost:5001/auth/callback
  6. Copy the Client ID and Client Secret

3. Configure Environment

GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
ADMIN_EMAIL=your-email@gmail.com

User Roles

The app uses a simple role-based access control system with three roles:

RolePermissionsHow to Get
user Analysis, screener, tracker, search history, settings Default role on first login
trader Everything in user + crypto bot + stock bot Granted via invite or admin assignment
admin Everything in trader + user management + system config ADMIN_EMAIL match or admin assignment
Role Hierarchy

Admins automatically have all trader permissions. Traders automatically have all user permissions. You don't need to assign multiple roles.

Invite System

Admins can pre-authorize users before they sign up:

  1. Go to the Admin tab
  2. Enter the user's email and select a role (user, trader, or admin)
  3. Click Invite
  4. When the user logs in with that email via Google OAuth, the role is automatically applied

Users who log in without an invite receive the default user role. The admin can later upgrade their role from the Admin panel.

ADMIN_EMAIL

The email address set in ADMIN_EMAIL automatically receives the admin role on every login. This ensures the primary admin can never be locked out, even if roles are misconfigured in the database.
